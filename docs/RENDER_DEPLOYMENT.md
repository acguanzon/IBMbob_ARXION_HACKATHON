# Deploying Arxion on Render

Arxion deploys as three Render resources managed by the root `render.yaml` Blueprint:

1. `arxion-postgres` — PostgreSQL database
2. `arxion-api` — Fastify API and Socket.IO web service
3. `arxion-web` — Next.js web service

The MCP server and IDE bridge remain local tools. They are not hosted as Render web services.

## Blueprint deployment

1. Push `render.yaml` to the repository's default branch.
2. In Render, select **New > Blueprint**.
3. Connect `acguanzon/IBMbob_ARXION_HACKATHON`.
4. Select the repository's root `render.yaml`.
5. Enter the requested secret values:
   - `MCP_API_KEY` — a long random secret used by locally running MCP adapters.
   - `GITHUB_TOKEN` — a token with repository read access. It is optional for public repositories,
     but required to connect private repositories.
6. Apply the Blueprint.
7. Wait for the database and both web services to deploy.
8. Confirm the API health endpoint at `https://<api-host>/health`.
9. Open the web service URL and register the first user.

The Blueprint dynamically supplies:

- the database's internal connection string as `DATABASE_URL`;
- the web service's public URL as the API's `CORS_ORIGIN`;
- the API's public URL as the web app's `NEXT_PUBLIC_API_URL` and `NEXT_PUBLIC_WS_URL`.

No Render root directory is configured because both applications depend on packages from the pnpm
workspace root.

## API settings

| Setting        | Value                                                        |
| -------------- | ------------------------------------------------------------ |
| Type           | Web Service                                                  |
| Runtime        | Node                                                         |
| Region         | Singapore                                                    |
| Branch         | `main`                                                       |
| Root directory | blank                                                        |
| Plan           | Free in the Blueprint; upgrade for persistent production use |
| Health check   | `/health`                                                    |

Build command:

```bash
npm install -g pnpm@9.15.4 && NODE_ENV=development pnpm install --frozen-lockfile --prod=false && pnpm --filter @arxion/types build && pnpm --filter @arxion/config build && pnpm --filter @arxion/database build && pnpm --filter @arxion/api build
```

Free-plan start command:

```bash
pnpm --filter @arxion/database exec prisma migrate deploy && pnpm --filter @arxion/api start
```

The migration command is idempotent and runs before the API process starts. On a paid Render web
service, move the Prisma command into the service's **Pre-Deploy Command** and use this start command:

```bash
pnpm --filter @arxion/api start
```

API environment variables:

| Variable           | Source                                                    |
| ------------------ | --------------------------------------------------------- |
| `NODE_VERSION`     | `22.18.0`                                                 |
| `NODE_ENV`         | `production`                                              |
| `DATABASE_URL`     | Render database internal connection string                |
| `CORS_ORIGIN`      | Render web service external URL, without a trailing slash |
| `INTERNAL_API_KEY` | Generated by Render                                       |
| `MCP_API_KEY`      | Secret entered during Blueprint creation                  |
| `GITHUB_TOKEN`     | Secret entered during Blueprint creation                  |
| `LOG_LEVEL`        | `info`                                                    |

Render provides `PORT`; do not hardcode it. The API already defaults to host `0.0.0.0`.

## Web settings

The Next.js application uses dynamic Server Components, so it must be a Web Service rather than a
Static Site.

| Setting        | Value                 |
| -------------- | --------------------- |
| Type           | Web Service           |
| Runtime        | Node                  |
| Region         | Singapore             |
| Branch         | `main`                |
| Root directory | blank                 |
| Plan           | Free in the Blueprint |
| Health check   | `/login`              |

Build command:

```bash
npm install -g pnpm@9.15.4 && NODE_ENV=development pnpm install --frozen-lockfile --prod=false && pnpm --filter @arxion/types build && pnpm --filter @arxion/web build
```

Start command:

```bash
pnpm --filter @arxion/web exec next start -H 0.0.0.0 -p $PORT
```

Web environment variables:

| Variable              | Source                                                               |
| --------------------- | -------------------------------------------------------------------- |
| `NODE_VERSION`        | `22.18.0`                                                            |
| `NODE_ENV`            | `production`                                                         |
| `NEXT_PUBLIC_API_URL` | Render API external URL                                              |
| `NEXT_PUBLIC_WS_URL`  | Render API external URL; Socket.IO upgrades it to a secure WebSocket |

`NEXT_PUBLIC_*` values are embedded during `next build`. Rebuild the web service after changing
either URL.

## Local MCP configuration for the hosted API

Continue running `apps/mcp-server` on the developer machine. Point it at Render:

```env
MCP_API_BASE_URL="https://<api-host>.onrender.com"
MCP_API_KEY="the-same-secret-entered-in-render"
```

The MCP adapter remains a stdio process launched by the coding-agent environment.

## IDE bridge behavior

`apps/ide-bridge` is designed to run on the user's computer and open local coding tools. It should
not be deployed to Render. If the hosted browser cannot reach the local bridge, the Agent Dock uses
the manual copyable handoff flow.

## GitHub webhook URL

After connecting a repository, configure its GitHub webhook to point to:

```text
https://<api-host>.onrender.com/webhooks/github/<arxion-repository-id>
```

Use the same webhook secret stored for that Arxion repository connection.

## Demo-plan limitations

The Blueprint uses free resources for convenience. Free web services can sleep when unused, which
causes cold starts. Free Render PostgreSQL databases have platform retention and capacity limits.
Use paid resources before treating the deployment as persistent production infrastructure.
